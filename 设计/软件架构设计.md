**硬件：** 微雪 ESP32-S3-Touch-LCD-3.49-V2（ESP32-S3R8：双核 240MHz / 512KB SRAM / 8MB PSRAM / 16MB Flash / QMI8658 IMU）

## 1. 设计目标与约束

| 项 | 内容 |
|---|---|
| 功能范围 | 需求八大模块：时钟、天气、语音、提醒、声音中心、相册、夜间模式、倒计时器；三场景：早晨/专注/睡眠 |
| 产品形态 | **横卧桌面**：界面默认横屏（640×172），IMU 自动在左横/右横间旋转；竖放为倒计时启动手势 |
| 核心原则 | **本地优先**——断网时时钟/闹钟/提醒/白噪音/设备控制必须完整可用；网络仅增强天气与对时 |
| 资源约束 | 双核 CPU；LVGL 全帧渲染已占 PSRAM ~440KB×2 + 横屏软件旋转缓冲 ~220KB；语音模型占 Flash ~3-10MB；中文字体 1-2MB |
| 已验证基建 | QSPI 屏+触摸+背光（10 例程，软件旋转机制现成）；ES8311 播放 / ES7210 双麦录音（08 例程，esp_codec_dev）；RTC/IMU/SD/电池（02/03/04/07 例程） |

## 2. 总体架构（四层）

```
┌─────────────────────────────────────────────────────────┐
│  UI 层（LVGL，core 0，横屏 640×172）                        │
│  app_ui：状态栏 + 页面导航 + 各功能页面 + 夜间/息屏表现        │
├─────────────────────────────────────────────────────────┤
│  功能服务层（core 0/1，事件驱动）                            │
│  app_clock   app_alarm    app_reminder   app_audio       │
│  app_voice   app_weather  app_scene      app_album       │
│  app_motion(姿态/方向)  app_timer(倒计时)                   │
├─────────────────────────────────────────────────────────┤
│  平台服务层                                                 │
│  app_event（事件总线） app_storage  app_net  app_power     │
├─────────────────────────────────────────────────────────┤
│  BSP 层（板级驱动）                                         │
│  bsp_lcd(现) bsp_bl(现) bsp_i2c(现) bsp_codec(移植08)      │
│  bsp_rtc(PCF85063) bsp_sd  bsp_imu(QMI8658) bsp_power     │
└─────────────────────────────────────────────────────────┘
```

**依赖规则：** 上层依赖下层，禁止反向；功能服务之间**不直接互调**，一律通过事件总线解耦（例：语音命令 → 事件 → 闹钟服务执行 → 事件 → UI 刷新 + TTS 播报确认）。

│   ├── app_album/           # 相册：SD 图片轮播、间隔设置
│   ├── app_scene/           # 场景引擎：早晨/专注/睡眠（动作表驱动）
│   ├── app_motion/          # 姿态服务（IMU 中断驱动）：方向判定(左横/右横,全局)、

│   ├── app_timer/           # 沙漏倒计时：≤30min、点击/竖放启动、漏沙动画联动、滴滴

## 4. 事件模型（系统骨架）

采用 ESP-IDF `esp_event`（默认循环 + 一个自定义 `LL_EVENT` 循环）。

**核心事件清单（V0.1 草案）：**

| 事件 | 载荷 | 生产者 → 消费者 |
|---|---|---|
| `LL_EV_TIME_SYNCED` | — | app_net → app_clock/UI |
| `LL_EV_ALARM_FIRED` | 闹钟 ID | app_alarm → UI/app_scene/app_voice |
| `LL_EV_ALARM_SNOOZE` | 闹钟 ID | UI/语音 → app_alarm |
| `LL_EV_REMINDER_FIRED` | 提醒 ID | app_reminder → UI/app_audio/app_voice |
| `LL_EV_VOICE_CMD` | 命令 ID + 参数 | app_voice → 各功能服务 |
| `LL_EV_PLAY_REQUEST` | 源类型(白噪/TTS/提醒音)+资源 ID | 各服务 → app_audio |
| `LL_EV_PLAY_STATE` | 播放/暂停/结束 | app_audio → UI |
| `LL_EV_WEATHER_UPDATED` | 地点 ID | app_weather → UI/app_scene |
| `LL_EV_NET_STATE` | 连接/断开 | app_net → UI/天气/时钟 |
| `LL_EV_SCENE_ENTER/EXIT` | 场景 ID | UI/闹钟 → app_scene → 各服务 |
| `LL_EV_BRIGHTNESS` | 级别/渐变参数 | 语音/UI/场景 → app_power |
| `LL_EV_BUTTON_TIME_SET` | — | UI → app_clock |
| `LL_EV_ORIENTATION` | 左横/右横 | app_motion → app_ui（触发界面旋转） |
| `LL_EV_GESTURE_STANDUP` | — | app_motion → app_timer（竖放手势,**仅沙漏页待机时发出**） |
| `LL_EV_GESTURE_SHAKE` | — | app_motion → app_power（晃动手势,**仅夜灯页前台且灯关时发出**） |
| `LL_EV_NIGHTLIGHT_STATE` | 开/关 | app_power → UI（同步小夜灯页开关状态） |
| `LL_EV_BATTERY_STATE` | 电量%/充电中/供电来源 | app_power → UI（**仅主页显示**）、app_net/app_weather（触发联网档位切换） |
| `LL_EV_SCREEN_STATE` | 亮屏/息屏 | app_power → UI/各服务（息屏时手势停发、唤醒时恢复） |
| `LL_EV_TIMER_FIRED` | 剩余 0 | app_timer → app_audio(滴滴音)/UI |
| `LL_EV_TIMER_STATE` | 运行/取消/剩余 | app_timer ↔ UI |

语音命令统一走 `LL_EV_VOICE_CMD` 路由（命令 ID 枚举 + 简单参数结构），各服务订阅自己的命令子集——新增命令不改路由代码。

## 5. 任务模型（双核分工）

| 任务 | 核 | 优先级 | 栈 | 周期/触发 |
|---|---|---|---|---|
| `ui_task`（LVGL timer_handler） | 0 | 4 | 8KB | 现有实现迁移，保持不变 |
| `audio_feed`（I2S 采音 + AFE + WakeNet/MultiNet 推理） | **1** | 5 | 16KB | 持续，feed 20ms 帧 |
| `tts_task`（esp-tts 流式合成 → 播放） | 1 | 4 | 16KB | 按需 |
| `audio_out`（播放写 I2S） | 1 | 4 | 8KB | 按播放会话 |
| `net_task`（WiFi/SNTP/天气拉取） | 1 | 3 | 6KB | 事件+定时 |
| `alarm_tick`（闹钟/提醒检查） | 0 | 2 | 4KB | esp_timer 每秒 |
| `motion_task`（IMU 中断驱动） | 0 | 2 | 4KB | QMI8658 Any-Motion/姿态中断触发,免轮询;中断内判定方向/手势 |
| `batt_task`（电池监测） | 0 | 1 | 3KB | 30s 周期 ADC（充电时 10s），滑动平均去抖;监测 GPIO16 供电来源切换 |
| `scene_task`（场景动作编排） | 0 | 2 | 4KB | 事件触发 |

**分工原则：** core 0 = 界面与逻辑（实时性要求低），core 1 = 音频/语音推理与网络（吃 CPU、有实时性要求）。ESP-SR 推理与 LVGL 渲染分核，避免互相卡顿（两者是本产品最大的两个 CPU 消耗者）。

**中断：** RTC_INT（TCA9554 PP4）→ 掉电后闹钟唤醒；触摸 INT 保持现状。

## 6. 音频管线（输入/输出分离 + 输出仲裁）

### 输入（语音识别）
```
ES7210 双麦 ─I2S(16k/32bit)→ AFE(AEC/降噪/波束)
    → WakeNet(常驻,唤醒词"Hi,乐鑫")
    → [唤醒后] MultiNet5(中文命令词,≤200条,支持运行时增删)
    → LL_EV_VOICE_CMD
```
- 唤醒期间播放需暂停或 AEC 对消（AFE 支持），集成时实测回声抑制效果
- 平时可关闭 feed 省电，夜间模式保持低功耗监听（可选）

### 输出（统一仲裁,单会话）
```
播放请求(LL_EV_PLAY_REQUEST)
   ↓ app_audio 会话管理器（优先级: 提醒音/闹钟 > TTS播报 > 白噪音/氛围音）
   ├─ 抢占: 高优先级打断低优先级（闹钟停白噪音）
   ├─ 压低(ducking): TTS 播报时白噪音降到 20% 播完恢复（睡眠场景友好）
   └─ 排队: 同级按请求顺序
   ↓ esp_codec_dev_write → ES8311 → NS4150B → 喇叭
```
- 白噪音源:Flash 内置若干条核心音（雨/海浪/溪流…,PCM 打包）+ SD 卡扩展库
- **UI 提示音（V0.2）**：滴滴（倒计时结束）、闹钟铃、按键音等短提示音统一编入固件资源表，优先级最高档
- 睡眠定时/音量渐弱由 app_audio 的会话参数实现

## 7. 存储设计（V0.2 细化：资源与信息文件怎么放）

**总原则：按"可靠性要求"分级——设备没插 SD 卡也必须完整工作的数据放 NVS/固件；可再生的媒体资源放 SD/Flash FAT。**

### 7.1 四级存储分工

| 级 | 介质 | 放什么 | 理由 |
|---|---|---|---|
| ① NVS（板载 Flash，必在、掉电可靠） | 键值 | 用户设置、闹钟、提醒、地点、倒计时偏好、**天气精简缓存** | 断网断卡核心数据；任何场景不可丢 |
| ② 固件内置（factory 分区内 EMBED） | 只读 | ESP-SR/esp-tts 模型、中文字体、核心白噪音 6-10 条、UI 提示音（滴滴/闹钟铃） | 开箱即用，版本升级随固件原子更新 |
| ③ SD 卡（可选，热插） | FAT | 白噪音扩展库、相册图片、天气原始 JSON（调试用） | 大容量可再down载资源，拔卡即降级 |
| ④ Flash FAT 分区（预留 ~3.9M，暂不启用） | FAT | 无 SD 时的示例图片/扩展资源兜底 | 后期视体积启用 |

### 7.2 NVS 键规划（namespace: `ll`）

> NVS 约束：单条 blob 上限 ~4000 字节（页大小限制），超过必须拆分——天气缓存按此设计。

| 键 | 类型 | 内容 | 大小预估 |
|---|---|---|---|
| `settings` | blob | 亮度/音量/夜间时段/贪睡时长/界面方向偏好/降温提醒阈值(默认4℃) | <512B |
| `alarms` | blob | 闹钟条目数组（每条 ~16B，上限 32 条） | <1KB |
| `reminders` | blob | 提醒条目数组（每条 ~64B，上限 32 条） | <2KB |
| `locations` | blob | 地点：和风 LocationID/名称/用途 | <512B |
| `wx_cur_<id>` | blob | 每地点**精简后**当前+24h 预报（仅存 UI/播报所需字段，丢弃原始 JSON） | ≤3.5KB/地点 |
| `wx_yday_<id>` | blob | **每日温度快照**：日期+最高/最低/体感（V0.4，供今昨对比，写满滚动覆盖） | ~32B/地点 |
| `wx_meta` | blob | 各地点缓存时间戳 + 拉取状态 | <128B |
| `wifi_cred` | blob | WiFi SSID/密码（读写保护组） | <128B |
| `timer_pref` | u8 | 倒计时常用时长 | 1B |

### 7.3 SD 卡（TF）布局

```
/whitenoise/   白噪音扩展库（16bit PCM 或 WAV，按目录=分类）
/album/        相册图片（JPEG/PNG，轮播来源）
/cache/        天气原始 JSON（仅调试，正式缓存走 NVS）
```
**SD 拔出降级**：声音中心只显示内置音源；相册页提示无卡；其余功能不受影响。

### 7.4 分区表调整（`partitions.csv`，16MB Flash）

| 分区 | 现在 | 调整为 | 用途 |
|---|---|---|---|
| nvs | 0x6000 | 0x6000 | 不变 |
| phy | 0x1000 | 0x1000 | 不变 |
| factory | 0x800000(8M) | **0xC00000(12M)** | app + 语音/TTS 模型 + 中文字体 + 内置白噪音 + 提示音 |
| （剩余 ~3.9M） | — | 保留暂不分区 | 视固件实际体积决定是否建 storage(FAT)（开放问题②） |

### 7.5 天气缓存策略（离线可用）

1. 拉取成功 → 解析出 UI/播报所需精简结构 → 写 `wx_cur_<id>` + 时间戳（NVS，断电保留）
2. 断网显示 → 读 NVS 缓存，页面标注"数据截至 HH:MM"；超 6 小时标注"数据过期"
3. 缓存读取失败/无缓存 → 显示"暂无数据"，不阻塞页面
4. 原始 JSON 仅在调试模式落 SD `/cache/`，不参与正式链路

### 7.6 中文字体
- LVGL CJK 字体：思源黑体子集（GB2312 常用 3500 字 + 天气/星期专用字），约 1-2MB 编入固件（`lv_font_conv` 离线生成）
- 大号时钟数字用专用数字字体（体积小、渲染快）

## 8. 时间与闹钟策略

```
上电 → 读 PCF85063 立即有正确时间（掉电走时）
     → WiFi 连上 → SNTP 对时 → 校写 PCF85063 → LL_EV_TIME_SYNCED
运行中: app_clock 统一提供当前时间（缓存 RTC 读取,每分钟校验）
闹钟触发: alarm_tick 每秒比对（运行时）；
         掉电场景由 RTC_INT(PCF85063 定时) 经 TCA9554 唤醒（后期低功耗阶段）
```

贪睡：触发后 N 分钟重响（默认 5，可设），状态在 NVS 持久化（重启不丢）。

## 9. 网络与天气

- `app_net`：STA 连接（凭证 NVS）、`LL_EV_NET_STATE` 广播；**断网不影响任何本地功能**
- **联网档位（V0.6，由供电状态驱动,见 §11b）**：

| 供电 | 天气拉取 | SNTP 对时 | WiFi 模式 |
|---|---|---|---|
| USB/充电在线 | 每 30min | 每 6h | 常连接 |
| 电池供电 | 每 2h | 每 12h | modem sleep（空闲关射频） |

- **无 WiFi 处理（V0.6）**：连接失败即**停止扫描** → 每 10min 单次退避探测 → 连续 3 次失败进**离线模式**（冻结全部网络任务,数据用 NVS 缓存,UI 显示离线图标）→ **按键唤醒或插电时**恢复探测
- `app_weather`：和风天气 API（地点 = LocationID 存 NVS）
  - 拉取节奏：启动 + 每 30min + 闹钟触发时（供早晨播报）
  - 缓存：最后一次数据 + 时间戳入 NVS，断网 UI 显示"数据截至 xx:xx"
  - 通勤提醒：本地/工作两地逐小时对比 → 雨/温差/带伞建议文案 → 交 TTS
  - **今昨温度对比（V0.4）**：每天首次拉取成功时，把当日预报最高/最低/体感写入 `wx_yday_<id>` 快照（带日期，滚动保留）；对比今日 vs 昨日快照 → 降幅超阈值（默认 4℃，可设置）生成降温提示 + 按体感温度查穿衣建议表 → 随 `LL_EV_WEATHER_UPDATED` 一并下发 UI/TTS。快照缺失（首日/昨日断电）→ 不显示对比，不报错。**不依赖和风付费的历史天气 API**
  - 穿衣建议表（体感温度分档，内置 6 档）：≥28℃ 短袖 → 22-27 薄 T → 16-21 T+薄外套 → 10-15 毛衣夹克 → 4-9 大衣薄羽绒 → <4 厚羽绒+保暖；叠加降温时文案强化"比昨天冷 X℃，记得加衣"
- API Key 与凭证不入 git（NVS 运行时配置 + `sdkconfig` 预置开关）

## 10. UI 架构（LVGL 9，横屏 640×172）

### 屏幕策略：**横屏 640×172 + IMU 自动方向**（V0.2 变更）
- 逻辑分辨率 640×172（横向长条），flush 时经 LVGL 软件旋转到面板原生 172×640（机制沿用现有 `Rotated` 实现）
- `app_motion` 判定左横/右横 → `LL_EV_ORIENTATION` → app_ui 切换旋转方向（90°/270°）+ 触摸坐标换算，动画过渡
- 竖放（倒计时手势）**不旋转界面**——仅作为手势事件
- 性能：软件旋转每帧 ~220KB 数据换算，LVGL 已在 core 0 且横屏内容（时钟/天气）局部刷新区域小，预期流畅；**S1 骨架阶段实测帧率**，不达标再评估降低色深/局部旋转方案（风险①）

### 开机启动时序（V0.7 新增,需求 §四 开机体验）
```
bsp_lcd_init：
  面板初始化 → DMA 缓冲就绪 → 【直发全屏黑色(物理坐标顺序刷,~50ms)】
  → 点亮背光(屏幕纯黑,无花屏) → LVGL 初始化/任务启动
app_ui_init（持锁）：
  【开机图(若启用)：lv_image 绘制+立即刷新 → 让锁延时 3s → 删图】
  → 进入主界面
```
- 开机图接口：`BOOT_LOGO_ENABLE`/`BOOT_LOGO_IMG` 编译开关（app_ui.c），素材为横屏 640×172、RGB565、小端 C 数组（~214KB,flash 内 const，经 LVGL 渲染管线自动处理旋转与字节序）；禁用时纯黑直进主界面

### 页面与导航（横条布局）
```
┌──────────────────────────────────────────────┐
│ 状态栏:WiFi/闹钟/播放/倒计时/电池/时间 (常显)     │
├──────────────────────────────────┬───────────┤
│                                  │  纵向导航   │
│   主内容区(当前页面)                │  图标条     │
│                                  │  (右侧)    │
└──────────────────────────────────┴───────────┘
页面: 主页(时钟大数字+日期星期+天气摘要,**电池电量/充电状态(仅此页显示)**,默认页/夜间页)
      天气页 | 闹钟提醒页 | 声音中心页 | 沙漏倒计时页(满沙待机/漏沙动画,§11c) | 相册页 | 设置页
      小夜灯页(中央大号滑动开关,见 §11a)

> 电池显示规则（V0.5）：电量图标+百分比+充电⚡**仅在主页**（需求 §9）；低电量横幅与关机倒计时提示例外（全屏短暂提示）。
> 息屏规则（V0.6）：**无自动超时息屏**——USB 供电永不息屏;电池供电仅电源键短按手动息屏,**仅电源键唤醒（手机式,触摸不亮屏）**;系统事件（闹钟/提醒/倒计时结束）主动亮屏例外;沙漏计时中、小夜灯开启中**冻结息屏**。
```
- 页面切换带横向滑动动画；导航条随方向自动上下互换（旋转镜像）
- **导航模型（V0.6 增补,需求 §四）**：两级页面栈——一级为主导航页面（右侧图标条直接切换,平级）;二级为应用内子页（闹钟/提醒的新建编辑、地点管理、白噪音分类、相册浏览、设置子项等）以**页面栈 push/pop** 进入与返回。**统一返回规范**：所有二级页面左上角固定返回箭头 + **左边缘右滑手势**返回;返回保留上级页面状态;最多两级,不出现更深嵌套
- 夜间模式:全局主题切换（暗色+低亮度+精简主页）;息屏时段/渐暗曲线由 app_power 管理

### UI 线程纪律
所有页面只订阅事件刷新（如 `LL_EV_WEATHER_UPDATED`），不阻塞等待网络/语音；跨线程用 `lv_async_call` 投递。

## 11. 场景引擎（app_scene）

场景 = 触发条件 + 动作序列（声明式表,不写死流程）：

| 场景 | 触发 | 动作序列 |
|---|---|---|
| 早晨 | 闹钟响 + 用户停止闹钟 | TTS:时间 → 拉天气 → TTS:通勤提醒 → **TTS:降温提示+穿衣建议（V0.4，检测到降幅超阈值才播）** → UI 切天气页(含今昨对比条) → (可选)白噪音轻音乐 |
| 专注 | 手动/语音 | 白噪音(咖啡馆) → 亮度降到 N → 主页只显时间 → (可选)番茄钟(复用 app_timer) |
| 睡眠 | 手动/语音/定时 | 白噪音(助眠) → 屏幕渐暗 N 秒 → 播放 T 时长后音量渐弱停止 → 结束后:电池供电则息屏,USB 供电则维持夜间低亮度(V0.6) |

实现：`scene_def[]` 表（触发源/动作列表/超时），事件匹配启动，动作经事件总线分发到 app_audio/app_power/app_ui——场景引擎本身无业务逻辑,加新场景只加表项。

## 11a. 小夜灯状态机（app_power，V0.3）

**光源方案：屏幕即灯——整屏纯白 + 背光最亮（无额外硬件）。**

```
        ┌─ 手动滑开关 ON (UI)      ┌─ 手动滑开关 OFF (UI)
        ├─ 晃动手势 (SHAKE) ──┐    │
 [关] ──┴───────────────────→┤ [开] ────────────→ [关]
                            │  整屏白 + 背光100%
                            │  记录先前亮度/模式
                            └─ 开灯后再晃动：忽略（只开不关）
```

| 规则 | 设计 |
|---|---|
| 开灯途径 | ① 小夜灯页滑动开关拨到开；② 收到 `LL_EV_GESTURE_SHAKE` 且当前为关 |
| 关灯途径 | **仅** 小夜灯页滑动开关拨到关（晃动永不关灯） |
| 开灯动作 | UI 整屏白色层（置顶全屏白对象）→ 背光 100%；**保存先前的亮度值/夜间模式/息屏定时状态** |
| 关灯恢复 | 撤销白色层 → 恢复原亮度/夜间模式；息屏定时重新起算 |
| 模式优先级 | 小夜灯 > 场景/夜间模式/息屏（灯亮期间禁止自动息屏与场景调光）；闹钟响铃不受影响正常触发；**低电关机(5%)例外于小夜灯**：先 TTS+全屏提示"电量极低 60s 后关机"，倒计时内插上充电线可取消（V0.5） |
| 状态同步 | 开/关均广播 `LL_EV_NIGHTLIGHT_STATE`，UI 开关状态与真实状态单向以 app_power 为准（防 UI 与手势竞态） |
| 交互守则 | 晃动检测仅在灯**关**时生效,避免拿取/晃动板子造成其他误触发 |

## 11b. 电源档位状态机（app_power，V0.6）

**总开关 = 供电来源（GPIO16,USB 在线检测）：USB → 全功能;电池 → 低功耗。切换实时生效（插/拔电即切换档位,事件 `LL_EV_BATTERY_STATE` 广播）。**

### USB / 充电在线档
- 永不息屏、无任何低功耗限制;夜间仅切低亮度档
- 联网按常连接档（§9 表）;CPU 常规档

### 电池供电档
| 措施 | 实现 |
|---|---|
| **无操作降亮度**（V0.6 增补） | 亮屏 + 电池供电 + **20s 无触摸/按键** → 降至低亮度档（默认值可设置）;任意交互立即恢复。USB 供电无此策略 |
| **息屏 = 低功耗模式**（同一状态） | **进入**：仅电源键短按手动（无超时自动息屏）;**冻结条件**：沙漏计时中、小夜灯开启中 → 按键无效。进入后联动:灭屏 + CPU 80MHz + tickless auto light sleep（~40mA→~15mA）+ WiFi 射频休眠 + 手势检测停用 |
| **唤醒**（手机式） | **仅电源键短按**（触摸不唤醒,防误触/误亮）;**系统事件亮屏例外**:闹钟/提醒/倒计时结束 → 自动亮屏播报,**20s 无操作自动息屏回低功耗**（期间用户触摸 → 转正常亮屏,不再自动息屏）;**USB 插入 → 立即亮屏并切全功能档** |
| CPU 场景档位 | 正常使用 240MHz · 沙漏漏沙中 160MHz · 沙漏待机/漏完 80MHz · 小夜灯 80MHz+LVGL 停渲染 · 语音监听 240MHz;**触摸/按键中断 → 立即升 240MHz**（交互零感知） |
| 联网 | §9 电池档（2h/12h/modem sleep/无网冻结;离线模式恢复探测条件=按键唤醒或插电） |
| 外设 | IMU 中断驱动（免轮询）;音频空闲关功放 |

### 低电分级（叠加在电池档之上）
- ≤20%：主页横幅 + TTS 一次
- ≤10%：强制降亮度
- ≤5%：TTS+全屏"60s 后关机"倒计时 → 拉低 SYS_EN 关机保时;期间插电即取消

### 电源键（button 驱动,短按/长按双识别）
- 短按 = 亮/灭屏切换（灭屏受冻结条件约束）
- 长按 = 确认关机流程（例程 07 现成机制,SYS_EN 自锁）

## 11c. 沙漏倒计时实现（app_timer + app_ui，V0.6）

**渲染方案：轮廓图片 + 程序绘制沙面（混合）**
- 沙漏轮廓:一张透明背景图（资源极小）;沙子:程序绘制
- 上腔沙面高度 = 总高 × 剩余时间/总时长;下腔沙堆反向增长;中间流沙细线
- **联动原理:每帧按剩余毫秒直接计算沙面位置,不依赖动画帧计数** → 暂停沙停、恢复续漏、误差为零
- 布局（横屏 640×172）:沙漏居中,左剩余时间大数字,右总时长/暂停/取消

**状态机**:`选时长 → 满沙待机(静止,80MHz) → 漏沙中(点击或竖放启动;160MHz,20-30fps 局部刷) → 沙空(滴滴+屏幕提示;80MHz) → 重来/退出`

**硬依赖：局部刷新改造（S1）**
- 现状瓶颈:厂商 main.c 为双全帧缓冲+full_refresh——任何像素变化都全帧软件旋转+全帧重发,动画不可行
- S1 改造为 direct/partial 模式:**仅脏区旋转+发送**;沙漏动画是局部刷新的验收标准（沙漏流畅即合格）
